### 2.3 迁移方式（两种，任选其一）

**方式 A：后端自动迁移（推荐，无需手工操作）**

启动 jar 时自动执行 `backend/src/main/resources/db/migration/V*.sql`：

- `V1__baseline.sql`：用 `CREATE TABLE IF NOT EXISTS` 描述**已有结构**（老库上是空操作，新机器上会建全表）
- `V2__auth_media_nodes.sql`：`ALTER TABLE` 加字段 + 建新表
- 执行记录写入 `schema_migrations` 表，**每个脚本只会执行一次**；遇到"列/索引已存在"会自动跳过

**方式 B：手动执行幂等脚本**

```bash
mysql -u<DB_USER> -p<DB_PASSWORD> --default-character-set=utf8mb4 bili_clone < docs/db/03_incremental_idempotent.sql
```

该脚本用 `information_schema` 判断列/索引是否存在，**可以重复执行**，不会报错、不会丢数据。

### 2.4 数据初始化（空库 → 有数据）

后端启动时 `DataSyncService` 会：

1. 检查 `videos` 表行数；
2. 为 0 → 把内置演示数据（16 位 UP 主 + 80 条稿件 + 1.5 万条弹幕 + 800 条评论 + 12 部番剧 + 动态 + 28 个内容节点）批量写入 MySQL；

## 三、登录认证（三种方式全部可用）

| 方式 | 接口 | 关键实现 |
| --- | --- | --- |
| 账号密码 + 图形验证码 | `GET /api/auth/captcha` + `POST /api/auth/login/password` | Java2D 生成 PNG（含干扰线/干扰点/旋转字符），存 `captcha_codes`，**5 分钟过期 + 一次性**（校验后立即置 `used=1`，校验失败也作废，防爆破）；密码用 **BCrypt** 存储 |
| 邮箱验证码 | `POST /api/auth/email/send` + `POST /api/auth/login/email` | 验证码存 `email_verification_codes`（10 分钟过期、一次性、60 秒频控、1 小时最多 10 次）；开发环境**打印到控制台并在接口返回 devCode**，生产环境走 `JavaMailSender` |
| 二维码登录 | `POST /api/auth/qr/create` + `GET /api/auth/qr/poll` + `/qr/scan` `/qr/confirm` `/qr/cancel` | ZXing 生成真实二维码（内容是 `http://host/#/qr/<qrId>`，手机可扫）；状态机 `WAITING → SCANNED → CONFIRMED`，另有 `EXPIRED`、`CANCELED`；确认后下发 token，桌面端轮询拿到即登录；过期可一键刷新 |

其它：`/api/auth/register`（注册）、`/api/auth/password/reset`（找回密码）、`/api/auth/password/change`（改密码）、`/api/auth/email/bind`（换绑邮箱）、`/api/auth/logout`（退出并删除 token）。

**安全与限流**：token 存 `user_tokens`（7 天），请求带 `Authorization: Bearer <token>`；`AuthInterceptor` 解析到 `UserContext`；
验证码接口 60 次/分/IP、登录 30 次/5 分/IP、注册 10 次/时/IP、发邮件 20 次/时/IP，全部走内存滑动窗口 `RateLimiter`。

**演示账号**：`bili_demo / bili123456`（首次启动自动创建并初始化密码哈希，用于体验密码登录和二维码"模拟手机确认"）。

**没有手机也能体验扫码**：登录弹窗/登录页的扫码 Tab 有「📱 模拟手机扫码」「确认登录」两个按钮，
也可以在浏览器新窗口打开 `/qr/<qrId>` 走完整的"手机端确认页"流程。

## 四、视频与封面（真实播放 + FFmpeg 截帧）

### 4.1 媒体链路

```
uploads/videos/*.mp4  ──FFmpeg 截帧(第3秒)──▶  uploads/covers/*.jpg
        │                                              │
        └──── /api/files/video/**（支持 HTTP Range）────┴── /api/files/cover/**
                        │                                      │
                   <video src>                          <img object-fit:cover>
```

- `MediaService` 启动时自动扫描 `uploads/videos`，用 FFmpeg 截帧生成封面，并把 `video_path / cover_path / duration / 宽高 / 文件大小` 写进 `videos` 表；
- FFmpeg 查找顺序：`FFMPEG_PATH` → PATH 里的 `ffmpeg` → `python -c "import imageio_ffmpeg"`（自带静态 ffmpeg）。**本机通过 `pip install imageio-ffmpeg` 提供的 FFmpeg 7.1 完成截帧**；
- 没有视频文件时：**自动用 FFmpeg 的 lavfi 测试源生成 10 个带音轨的演示视频**（`sample-01..10`），并把它们绑定到 10 条稿件上 —— 这样"真实播放 + 真实封面帧"开箱可验证；
- 视频文件通过 Spring 的 `ResourceHttpRequestHandler` 提供，原生支持 `Range`（已验证 `206 Partial Content`），所以进度条可以随意拖动；
- **兜底**：没有视频文件的稿件，前端用"渐变 + emoji + 封面帧（如果有）"占位，卡片和轮播都**不会被留白**。

### 4.2 封面优先级（前端 `VideoCard` / `HomeView` / `PlayerView`）

1. `coverUrl`（FFmpeg 截帧的真实封面）→ `<img object-fit:cover>` 铺满；
2. 图片加载失败 → `@error` 自动回落到 2；
3. 渐变色（`coverColor1/2`）+ emoji + 封面大字 → 一定铺满容器。

### 4.3 首页轮播空白问题的修复

**原因**：`.hero` 是 `display:grid`，右侧栏（热搜 + 登录卡）比 300px 的轮播高，grid 默认 `align-items: stretch` 把 `.banner-wrap` 拉高，而里面 Element Plus 轮播只有固定 300px，于是下方露出大片白色。

**修复**：
- `.hero { align-items: start; }`（不再拉伸）；
- `.banner-wrap` 用 `aspect-ratio: 16/6.4`（老浏览器用 `::before + padding-top` 兜底），最大高度 320px、最小 190px；
- 轮播容器高度改 `height="100%"` 并强制 `.el-carousel / .el-carousel__container { height:100% }`；
- 封面图 `position:absolute; inset:0; width:100%; height:100%; object-fit:cover; display:block`，并加白→透明渐变遮罩保证文字可读；
- 没有真实封面时用渐变 + emoji 铺满整块。

**自动验收结果**（`node tools/verify.mjs`）：

| 分辨率 | 轮播外框 | 可见项 | 铺满率 | 下方空白 | 横向滚动/溢出 |
| --- | --- | --- | --- | --- | --- |
| 1680×1050 | — | — | 0.998 | 0px / 0px | 无 / 0 |
| 1366×768 | 1002×320 | 1002×320 | 1.000 | 0px / 0px | 无 / 0 |
| 834×1112（平板） | — | — | ≥0.98 | 0px / 0px | 无 / 0 |

## 八、启动与测试

### 8.1 环境要求

| 依赖 | 版本 | 本机情况 |
| --- | --- | --- |
| JDK | 17+ | `D:\ProgramData\jdk\jdk-17` |
| Maven | 3.9+ | `D:\ProgramData\maven\apache-maven-3.9.11` |
| Node.js | 18+ | v24.11.1 |
| MySQL | 5.7+/8+ | 本机 3306，账号密码见 `.env`，库 `bili_clone`（已存在） |
| FFmpeg | 任意较新版本 | 可用 `pip install imageio-ffmpeg` 提供（后端会自动找到） |

### 8.2 一键启动（推荐）

```bash
# 1. 前端打包
cd D:\bilibili-clone\frontend
npm install --include=dev
npm run build

# 2. 产物复制到后端静态目录
xcopy /e /i /y dist\* ..\backend\src\main\resources\static\

# 3. 后端打包
cd ..\backend
mvn package -DskipTests

# 4. 启动（会自动连接 MySQL 并执行迁移）
java -jar target\bili-web.jar
# 打开 http://localhost:8080
```

Windows 上也可以直接双击项目根目录的 **`启动网站.bat`**（用已打包好的 jar）或 **`重新构建.bat`**（重新打包并启动）。

### 8.3 开发模式

```bash
cd frontend && npm run dev     # http://localhost:5173 ，/api 自动代理到 8080
```

### 8.4 测试命令

```bash
# 前端单元测试（26 个用例）
cd frontend && npm run test:run

# 页面 + 布局 + 轮播铺满 + 多分辨率自动验收（需要后端已启动）
cd .. && node tools/verify.mjs

# 三种登录方式端到端验收（真实点浏览器，验证码从 MySQL 读取）
node tools/e2e-auth.mjs

# 接口级验收（图形/邮箱/二维码 + 用户中心 + 收藏 + 设置 + 退出）
python tools/api-test.py          # 见 tools/api-test.py
```

### 8.5 手工验证步骤（5 分钟走完）

1. 打开 <http://localhost:8080> → 首页轮播应铺满（缩放窗口到手机宽度也不留白），
   正文出现"内容节点"宫格，卡片封面是真实视频帧（sample-01...）或渐变占位图，**没有空白**。
2. 点任意卡片进播放页 → `<video>` 能真实播放、能拖进度条、有声音；下方有"封面帧"条与播放量/发布时间；右侧相关推荐、下方评论区正常。
3. 点右上角"登录"→ 弹窗三个 Tab：
   - **密码登录**：`bili_demo` / `bili123456` + 图形验证码（点图片可刷新）→ 登录成功；
   - **邮箱登录**：输入任意邮箱 → 点"获取验证码" → 页面会直接显示开发环境验证码（也打印在控制台）→ 填进去 → 登录成功（新邮箱自动注册）；
   - **扫码登录**：出现真实二维码 → 点"模拟手机扫码"→"确认登录" → 桌面端自动登录；也可以点"在新窗口打开确认页"体验手机端。
4. 右上角头像 → 个人中心 → 依次查看 历史 / 收藏 / 消息 / 设置（可改主题、弹幕默认值、改密码、换绑邮箱）/ 我的投稿。
5. 点"投稿"→ 拖一个 mp4 进去 → 填写标题 → 立即投稿 → 成功后显示 FFmpeg 自动截出来的封面帧。
6. 地址栏随便输一个不存在的路由（如 `#/abc`）→ 出现 404 页面（不是空白）。
7. 侧边导航点"直播 / 专栏 / 活动 / 社区中心 / 纪录片"等预留节点 → 出现占位页（含后续扩展计划），**不会 404、不会空白**。

## 十、占位方案与后续扩展点

| 功能 | 现状 | 后续怎么扩展 |
| --- | --- | --- |
| 直播 / 专栏 / 活动 / 社区中心等 15 个预留节点 | 有路由、有入口、有占位页（含扩展计划） | 在 `categories` 表把 `is_placeholder` 改成 0，给 NodeView 增加对应 `node_type` 的分支渲染即可 |
| 视频清晰度切换 | 表 `video_sources` 已建好，接口 `/api/media/sources/{id}` 已通；演示视频只有一路，菜单里自动补 1080P/720P/480P 选项 | 给同一稿件插入多条 `video_sources` 记录，前端菜单会自动出现真实清晰度 |
| 真发邮件 | 开发环境走控制台 + devCode | 配好 `MAIL_HOST/MAIL_USERNAME/MAIL_PASSWORD`，把 `BILI_DEV_MODE` 设为 `false` |
| 扫码登录「手机端」 | 提供模拟按钮 + 可在手机浏览器打开 `http://<电脑IP>:8080/#/qr/<qrId>` 真实扫码确认 | 接 App 时把 `/api/auth/qr/scan|confirm` 换成 App 内的调用即可 |
| 投稿审核 | 上传后直接发布（`PUBLISHED`），`video_uploads` 有状态字段 | 改成 `REVIEWING` 并加一个后台审核接口即可 |
| 弹幕持久化的实时推送 | 轮询式（刷新后仍在） | 需要实时可接 WebSocket/SSE，`danmaku` 表结构无需改动 |
| 搜索 | 内存检索（标题/UP/分区/标签）+ `search_history` 表 | 数据量大时可换 MySQL FULLTEXT 或 ES，接口不变 |
